# 网络与端口

## 4.1 端口不通（从外到内逐层排查）

**排查顺序，不要跳步**

1. **服务是否在监听**：`ss -tulnp | grep <port>`。
   - 无输出 → 服务没起来，问题在应用侧，不要查网络。
   - 监听在 `127.0.0.1:<port>` → 只监听了本地回环，外部必然连不上。需要改成 `0.0.0.0`。这是最高频原因。
2. **本机能不能通**：`curl -m 3 http://127.0.0.1:<port>`。本机不通说明应用层问题。
3. **防火墙**：`iptables -L -n -v` 或 `firewall-cmd --list-all`（CentOS）/ `ufw status`（Ubuntu）。
4. **安全组/网络策略**（云主机）：控制台确认入方向规则，这一层在操作系统内部查不到。
5. **对端能否路由到**：`ping`、`traceroute`。

**判定要点**：严格按照"服务 → 本机 → 防火墙 → 安全组 → 网络"的顺序，每一层确认后再往下走。跳过前置层直接查网络是最常见的浪费时间。

## 4.2 连接数过高 / Too many open files

**现象**：报 `Too many open files`；新建连接失败。

**排查**
1. `ss -s` 看总连接数与各状态分布。
2. `ulimit -n` 与 `cat /proc/<pid>/limits | grep "open files"` 确认进程实际限制（注意区分 shell 的限制与 systemd 服务的限制，后者在 unit 里配）。
3. 按状态分组：`ss -tan | awk 'NR>1{print $1}' | sort | uniq -c | sort -rn`。`TIME_WAIT` 过多通常是短连接未复用；`CLOSE_WAIT` 过多是应用没正确关闭连接，属于代码问题。

**处置**
- `TIME_WAIT` 多 → 启用连接池/长连接，而不是调内核参数掩盖。
- `CLOSE_WAIT` 多 → 应用侧漏关连接，必须改代码。
- 确实需要提高上限 → 修改 `LimitNOFILE` 并 `daemon-reload`。

## 4.3 DNS 解析失败

**排查**
1. `cat /etc/resolv.conf` 看配置的 DNS。
2. `dig <domain> @<dns-server>` 指定 DNS 测试，区分是 DNS 问题还是网络问题。
3. `getent hosts <domain>` 走完整的 NSS 链路（包含 `/etc/hosts`），比 `ping` 更能反映应用侧的实际解析结果。
4. 检查 `/etc/hosts` 是否有错误条目覆盖了正常解析。

**处置**：DNS 服务器不通则换备用 DNS；内网域名解析失败通常是 DNS 服务器侧记录缺失，需要联系网络管理员。

## 4.4 网络延迟高 / 丢包

**排查**
1. `ping -c 20 <host>` 看丢包率与时延抖动。
2. `mtr <host>`（或有 `traceroute`）定位是哪一跳开始劣化。
3. `ss -i` 看 TCP 重传：`netstat -s | grep -i retrans` 重传率高说明链路质量差或拥塞。
4. 排除本机问题：`ping 127.0.0.1`、`ping <网关>`，确认是本机网卡还是外部链路。

**判定要点**：只在某一跳丢包且后续跳恢复正常，通常是该节点限速 ICMP，不代表真实故障。要结合 TCP 重传率判断。

## 4.5 带宽被打满

**排查**
1. `sar -n DEV 1 5` 或 `ifstat` 看实时流量与网卡上限。
2. `ss -tnp state established` 找流量最大的连接对端。
3. `iftop` / `nethogs` 定位到进程。

**处置**：确认是业务流量还是异常外联（挖矿、被入侵的常见特征）；限流或扩容前先确认流量性质。
